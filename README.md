# 厂务维修与保洁任务管理微信小程序

一个用于作品展示的原生微信小程序前端，围绕巡检发现问题、查看待办并派发任务、维修或保洁处理及统计查看组织页面与交互。

本仓库由实习期间完成的前端项目整理而来。厂区名称、业务团队名称和具体位置已替换为通用示例，保留两个厂区、维修与保洁两类业务及三类角色的流程设计。

## 个人贡献

- 梳理维修与保洁业务流程，重做小程序前端页面与交互，借助 AI Coding 辅助开发。
- 将检查员、管理员及维修或保洁人员的工作入口分开，按角色组织任务上报、审核分配、处理及统计。
- 根据业务人员反馈，复用并调整页面，将两个厂区的任务与位置选择分开。
- 原实习版本经约20名业务工作人员使用模拟数据试用，完成迭代并向公司技术人员交接前端代码。

## 功能

| 功能 | 内容 |
| --- | --- |
| 业务入口 | 厂区A与厂区B分别提供维修和保洁入口 |
| 问题上报 | 文字描述、图片选择、区域及子区域选择 |
| 任务管理 | 待办查看、人员分配、优先级、状态查看 |
| 处理反馈 | 维修或保洁人员查看任务、开始处理并提交反馈 |
| 历史记录 | 按任务状态查看处理记录 |
| 统计 | 任务数量、类型、区域和人员处理情况，支持CSV导出 |

## 技术与项目范围

- JavaScript、WXML、WXSS、JSON，使用微信开发者工具。
- 原生小程序项目，没有需要安装的第三方 npm 依赖。
- 任务及角色信息通过本地缓存保存，使用模拟角色与示例数据。
- 本仓库完成的是前端页面及业务交互，尚未接入后端接口、真实账号认证或跨设备数据同步。

## 本地运行

1. 下载仓库并解压。
2. 在微信开发者工具中导入包含 `app.js` 和 `app.json` 的项目根目录。
3. 导入时配置你本人有权限使用的 AppID。若工具提供测试号选项，也可选择测试号。本仓库已移除原项目 AppID。
4. 编译后，从入口页选择示例厂区与业务类型，再选择对应角色。
5. 可先用检查员身份创建一条示例任务，退出角色后以管理员身份分配，再切换到维修或保洁角色处理，最后查看统计与历史记录。

切换演示角色时使用页面内的退出或返回登录操作。需要重新开始演示时，可在开发者工具中清理本项目缓存。

## 整理与验证

展示版替换了厂区和位置数据，移除了原项目 AppID 与本机开发配置，并修复了检查中发现的角色跳转、弹窗事件绑定及任务完成方法拼写问题。

- 43个 JavaScript 文件通过语法检查，43个 JSON 配置文件可解析。
- 41个页面的配套文件、页面路径和事件处理方法已核对。
- 在模拟微信接口环境中验证了12种厂区与角色入口，以及四个业务模块的任务创建、分配、开始处理和完成流程，确认缓存分开保存。
- 以上检查不包含微信开发者工具编译、页面视觉预览、真机操作、拍照及文件分享；导入后仍需完成这些检查。
